## Refuted on code read (not reported)

| Candidate | Why refuted |
|---|---|
| `iimx_poll` `tmout<=0` hangs forever | Legacy loop has same `if (tmout>0) if ... break;` shape; comment at :954 documents parity |
| `iimx_local` treats `NIIMX^` as `IIMX_RFINISHED` | Code at :2618 explicitly tests `NIIMX^` prefix and sets `IIMX_RERROR` |
| `iimx_sendx_pool` `tmout<1→600` new default | Legacy applies same default at :4326 |
| `doGather` doesn't match `NIIMX^` prefix | Legacy `iimx_connect` failure body `FAILED^Could not connect to Host` didn't match `FAILED^Comm` either — not a regression |
| `iimx_sendx_call` divert routes remote through local `niimx.congested` | Real behavior change but already recorded in the design's 6 documented behavioural deltas |
| `niimx_xact` `strdup(literal)` returns not NULL-checked | All 5 sites copy the pre-existing legacy pattern verbatim (`iimx_snd.c` on main at :472, :551, :582, :600, :621). Callers already tolerated / crashed on the same shape before the toggle; not a regression. **Fixed in commit `bd0efc1` via `niimx_set_err()` helper, both new and legacy sites.** |
| `iimx_q` slot-clear discards callbacks + leaks Lua registry refs | **Fixed in commit `7777e3d`.** `iimx_snd.c` send-failure path now fires each earlier queued slot's callback with `"FAILED^Communication Error"` before clearing (the current failing slot deliberately skips the fire since `iimx_q` returns -1 to match legacy "not queued, no callback" semantics). `ilua.c` gains `luaL_unref` in `inc_iimxq_callback` after `lua_pcall` and in the `-1`-return branch of `inc_iimxq` — every fref created by `luaL_ref` at `:1568` is now paired with exactly one `luaL_unref` on both success and both failure paths |
| niimxd `unlink NIIMX_CONGESTED_FILE` at startup races a running instance | **Fixed in commit `f49777d`.** The unlink moved below `niimx_setup_zmq()`, so a second niimxd racing a healthy one fails inside `zmq_bind` and exits without touching the flag. The IPC socket path is the exclusion primitive we already have. Stale-flag-on-clean-startup case unaffected |
| niimxd `fchmod` 0666 on spill files was a regression from umask-respecting legacy | Finding was factually wrong. `cnc/dci/src/iimx.cc:2458` legacy is `mkstemp` + `vSystem("chmod 666")` — hardcoded 0666, umask-independent, identical to the new code. No regression. **However, the underlying "world-writable during the write→read window" concern is real and pre-existing; tightened in commit `aaf6021` to 0640 (group-readable) in the niimxd path only. Legacy `iimx.cc` stays at 0666 by design (its callers may be non-cmm)** |
| `iimx_sendx_batch_wk` and `iimx_sendx_multi` don't shed on congestion | **Fixed in commit `0b15a66`.** Both diverts now call `niimx_congested()` once per batch, before the send loop. On shed, every entry gets `state=IIMX_RERROR` and `b.buf="FAILED^Communication Error"`; rc stays 0 to preserve the legacy return contract that `get_host_wk()`'s `if (0 == ...)` guard and every other reader relies on. Body chosen to match `doGather`'s `strstr("FAILED^Comm")` and the unguarded `strncmp` in the azp readers |
| `niimx_next_msgid` signed shift UB when `getpid() >= 2^23` | Refuted on Linux. `PID_MAX_LIMIT` is architecturally capped at 4194304 (2^22) on 64-bit and 32768 on 32-bit, per the kernel's `pid.h`; sysctl `kernel.pid_max` cannot be raised above it. Max shift value 2^30, safely inside int32_t. Project is LINUX-only per design |
| `niimx_next_msgid` 256-wide collision misroutes replies | ROUTER routes by connection identity (per-DEALER-socket), not by msgid — two processes have two identities, replies route correctly regardless of msgid overlap. In-process `niimx_recv` demux only sees locally-generated IDs. `rspfile` filename uses `mkstemp` since commit `0981fb6`. The only remaining consequence is trace-log correlation at trace level 0-1 (four sites in `niimxd.cpp:1095, 1102, 1374, 2696`), where `msgid` is logged without `mpid` — cosmetic, mpid is on the wire and could be added to those trace lines if needed |
| Inconsistent post-conditions across diverted exported symbols | **Documented in commit `690c2ac`.** `_multi`/`_batch_wk` leave `b.buf="FAILED^..."` because their live readers deref unguarded; `_local`/`_pool` leave `b.buf=NULL` because theirs don't need one — deliberate per-function, not a bug. The header `include/iimx_snd.h` now names the four post-conditions in a table with the caller ergonomics that produced each, and states the audit obligation for anyone porting between them or writing a new consumer of `_pool`. No code change |
| `niimx_xact` NIIMX^ path leaves `*nbytes` nonzero | **Fixed in commit `86604fb`.** NIIMX^ rejection now zeroes `*nbytes` before the `-1` return, matching every other failure path and the `niimx_recv` header contract at `:264`. Callers that want the rejection body's length still have `strlen(*rsp)` — `niimx_recv` NUL-terminates |
| `iimx_sendxn` `memset(rsp, 0, n)` runs before the divert | **Fixed in commit `2db3ada`.** Both the entry `memset` and the divert's own `strncpy` now guard on `rsp && n > 0` |
| `strncmp(body, ...)` in `niimx_xact` without NULL guard | **Fixed in commit `c3f277b`.** Both prefix tests (`NIIMX^` and `NIIMX_RSPFILE_PREFIX`) short-circuit on `body != NULL` |
| Batch collect loop duplicated ~1200 lines across 4 diverts | **Documented in commit `bc5866f`.** A proper helper extraction is scheduled for a follow-up on a box that can run `test_niimx.sh`; here, a canonical SEE ALSO block at `iimx_sendx_multi` names what MUST match and what is deliberately per-function across the four sites, with cross-reference blocks at the other three pointing back to it. Anyone changing recv-loop policy is forced to notice the coupling in the diff |
| Local-host collapse triplet duplicated 4 sites | **Fixed in commit `f80245b`.** `niimx_normalize_host()` in `niimxlib` gathers `gethostname()` into a process-local cache and returns "" for NULL / "" / "localhost" / "2iimx" / own-name, `host` unchanged otherwise. All four call sites in `iimx_snd.c` swapped; their per-site `char me[]`/`char nme[]` buffers and `gethostname()` calls are gone. Adding a new alias — an IPv6 loopback, a config-tunable name — is now a one-line edit that reaches every entry point at once |
| `niimx_xact` makes 4 probe syscalls per command | Left alone. Real-workload probe overhead measures <1% of xact latency (2 µs `access` + 6.4 µs socket-probe triple, vs milliseconds-to-seconds for an NE command). Caching would either widen the fast-fail TOCTOU window on `niimx_avail` or violate the legacy-parity comment on `niimx_congested`. Both guarantees have measured operator value from earlier tasks. A better congestion-signalling design (SUB/PUB, kernel `flock`, or a versioned flag) is a follow-up when the current design's failure modes become the bottleneck. Documented as design debt above `niimx_congested()` in commit `0a4d2c11` |
| `niimx_send` frame-1 skip-drop relies on libzmq internals | **Fixed in commit `f82f79b`.** One rule for every frame — fail => drop — replaces the frame-1 special case. Rare EINTR at the delimiter during a pipelined batch now loses the in-flight replies with the socket, which is a slightly-more-likely instance of a case callers already handle on frames 2..7 rather than a new failure mode. Removes the libzmq-implementation-detail dependency. `sendfail1` test's needle inverts (`SENDFAIL1_OK=0 rc2=-2 aligned=1`) and its driver/comments follow |
| `strncmp(body, "NIIMX^", 6)` without NULL guard | **Fixed in commit `c3f277b`.** Both prefix tests in `niimx_xact` (`NIIMX^` and `NIIMX_RSPFILE_PREFIX`) now short-circuit on `body != NULL` before the `strncmp`. Latent — `niimx_recv` currently always allocates — but the header contract does not forbid a NULL body, and this closes the "future optimisation skips the realloc" trap without any behavioural change today |
| `rj_gui_cgi` rspfile callers don't check rc, silent empty page | Legacy `iimx_sendx_call` fills `*rrsp` with the same error strings ("Timeout", "Service Unavailable", "iimx is busy…", "System Failure", `ebuf` sprintfs) and returns -1. `rj_gui_cgi_almlist`/`_map` at `:321`/`:382`/`:578` ignore rc, wrap `rrsp` in `std::string`, parse — the parser finds no LINK^/DCS^/ALM^ prefix and produces empty output either way. **Same silent-empty-page under USE_NIIMXD=0.** Preexisting caller-side bug in `rj_gui_cgi`; documented and not fixed under this toggle work |

## Deploy-time gaps still open (from the plan, not the review)

Recorded here because a reviewer will ask.

1. **No real `niimxd` has ever run against this.** Daemon-side behaviour is verified by extracting functions verbatim at build time and driving them, or against the `niimx_stub` test double. `niimxd` exits at `ddb_init(GET)` with CNC down.
2. **The `niimx.congested` flag lifecycle is compile-verified only.** If wrong, the failure mode is a permanently shed box. Watch on the first CNC-up target.
3. **Deploy is not partial-safe.** `niimxd` and `libinc.so` share the wire format and must ship together. `libinc.so` must reach `/usr/cnc/lib`; consumers carry no RPATH.
